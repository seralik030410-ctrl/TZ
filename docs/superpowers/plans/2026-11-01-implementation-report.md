# Результат правок «Ритма» — 01.11.2026

Рабочая ветка: `codex/november-planner-fixes`, база `314206e`. Изменения локальные, без push/deploy. Production-миграция и фактическое архивирование задач не выполнялись.

## Что изменено

- Внутри занятия на главной и в расписании есть «Задача внутри занятия»: новая задача сразу со списком шагов либо существующая личная задача вместе с подзадачами. Создание дерева — одна серверная транзакция; прежние активные блоки при привязке убираются. Каждый шаг можно отметить прямо внутри пары.
- Повтор 09:00 может привязаться к паре 08:00–12:00 по включению интервала. При двух пересекающихся подходящих занятиях случайный выбор не выполняется. В форме повторов доступны время и список шагов.
- Связанные с парой задания и дочерние шаги исключены из самостоятельного планирования в UI и контракте сервера.
- Расписание — первый содержательный блок главной. Задача AZ Plus с частичным размещением остаётся видимой: из 120 минут после размещения 30 отображается остаток 90 минут.
- Автоплан учитывает существующие блоки, прямые плановые интервалы, текущее время, срок и зависимости. Два личных этапа не используют одно и то же свободное окно. Архив одиночной задачи убирает её активные блоки; Today не рисует осиротевшие блоки.
- У этапов появились отдельные действия распределения. Старые задачи без этапа видны в ветке «Без этапа»; общее действие ищет этап с оставшейся работой.
- Вкладки задач и дней недели работают стрелками/Home/End, связаны с панелями. Дата расписания не очищается до Invalid Date; исключение открывается на просматриваемый день. Подписи редактирования исправлены.
- Модальные окна вынесены в portal: карточки с анимацией больше не ограничивают fixed overlay. Автофокус исключает hidden input и скрытый native select Radix; trap исключает недоступные элементы.
- Улучшены перенос текста/резерв под delete в timeline, вложенная ветка проекта, денежные строки и узкие панели. Текущий стиль сохранён.
- Список валют формы согласован с сервером: USD/TJS/RUB/EUR/KZT, без тихой замены EUR/KZT на TJS. Ошибки валидации валюты представлены понятным текстом вместо сырого Zod JSON.
- «Неделя» ограничивает историю обеими границами периода и считает завершения по completedAt.
- Добавлен обратимый архив личных заданий с preview/counts/revision, batch snapshot, идемпотентным commit и восстановлением с проверками изменений/конфликтов. Общие задачи и актуальные экземпляры повторов сохраняются. В Tasks есть фильтр личных задач со счётчиком сохранённых общих.
- Серверный taskEpoch защищает от старых очередей и отмены раскладки. Старые task mutations остаются в карантине на устройстве; финансовая очередь сохраняется. Undo проверяет поколение самого журнала, а не только текущий заголовок запроса.
- Общие данные/хуки ModuleKit вынесены в `src/lib/moduleData.ts`, что устранило пять существовавших lint-ошибок без отключения правил.

## Пределы готовности

Архив и миграция `0013_task_archive.sql` **не проверены на реальном MySQL**: в текущем окружении нет отдельной тестовой БД/локальных mysql/docker. Контрактные тесты и статическая проверка не заменяют интеграционные сценарии rollback/commit/restore и одновременных запросов. Поэтому фактический сброс не выполнялся, production-ready статус архива не заявляется.

Реальный zoom 125/150%, тёмная тема, экранная клавиатура телефона и полный keyboard regression не завершены. Пять ширин не выдаются за проверку настоящего browser zoom. Скриншоты показывают fixture, а не опубликованное приложение. Финансовые markPaid/права двух профилей в реальном MySQL повторно не исполнялись.

Перед выпуском: копия MySQL → миграция и повторный запуск → архив/restore/rollback/epoch с двумя профилями и устройствами → обязательные платежи и общий слот → оставшиеся визуальные проверки → deploy и сверка SHA/health. До этой проверки приложение не заявляется полностью принятым в production.

## Принятые решения

- Работа в существующем checkout на отдельной ветке сохраняет пользовательский контекст и два исходных документа; новая worktree не создавалась по указанию работать без лишних вопросов.
- Регулярные ноябрьские задачи остаются в активном списке: это осознанное исключение из «чистого списка», чтобы не потерять понедельник 09:00 и пять шагов.
- Реализация кода не означает разрешение на непроверенный production reset или публикацию. Изменения данных отложены до интеграционной проверки.
