# Аудит интерфейса «Ритм» — 01.11.2026

## Область и ограничения

Проверены исходники текущего `HEAD` (`314206eb6650801cc78f1d1ff0a27883709182de`) и production UI в существующей вкладке Brave: `/schedule`, выбранное воскресенье 01.11.2026, Asia/Dushanbe. Рабочее дерево содержит только исходный незакоммиченный план сброса. Просмотр страницы был read-only. Не удалось подтвердить соответствие production текущему HEAD: Railway-панель и deploy metadata не открывались; коммит релиза неизвестен. Проверка остальных страниц и заданных viewport/zoom не завершена, поэтому это частичный аудит, без заявления о полном прохождении.

## Предварительные наблюдения (оценка уточнена ниже)

### Снято: разные количества событий на разных днях недели

- **Где:** `/schedule`, блок «День недели» и поле даты.
- **Воспроизведение:** открыть production расписание на 01.11.2026; дата в поле — «1 нояб. 2026 г.», выбранное воскресенье показывает две записи, понедельник — три.
- **Наблюдение:** подпись первой вкладки содержит «Пн 3 соб.», хотя календарная дата 1 ноября 2026 приходится на воскресенье. UI не разъясняет, что верхняя полоса является недельным шаблоном, а выбранная дата — отдельными исключениями на дату. На экране это выглядит как несогласованное число событий.
- **Уточнение по коду:** это штатное поведение, не дефект. `Schedule.tsx` вычисляет количество для каждой даты той же недели через `addCalendarDays(viewDay, day.value - selected)`. Воскресенье не должно иметь то же количество, что понедельник. Переработка переключателя на этом основании не нужна.
- **Доказательство:** accessibility tree страницы (дата `2026-11-01`, «Воскресенье», карточки «Только 2026-11-01»; вкладки недели показывают собственные количества) и визуальный снимок production.

### Не подтверждено как дефект: CTA за sticky-шапкой при прокрутке

- **Где:** верх страницы `/schedule`, кнопка «Добавить событие».
- **Воспроизведение:** открыть страницу с сохранённым положением прокрутки; верхний заголовок и кнопка оказываются частично над viewport, sticky-шапка их закрывает.
- **Ожидание:** заголовок и основной CTA доступны целиком после загрузки/перехода; sticky элементы не перекрывают содержимое. Неясно, вызвано ли это сохранённой прокруткой браузера или поведением страницы, поэтому при реализации воспроизвести на чистом входе и после навигации.
- **Доказательство:** визуальный снимок текущей вкладки; на верхнем краю видна часть текста пояснения и красной кнопки за фиксированной шапкой.

## Кодовые риски, требующие отдельной проверки

- `api/queries/routines.ts`: генератор просматривает 8 дат для шаблона с одним днём недели, иначе только текущий день. Уточнено: `createOnce` в `api/moduleStore.ts` НЕ воскрешает существующий `isDeleted`. Поэтому архивирование уже созданных ноябрьских повторов может погасить их навсегда, пока tombstone существует; нужна отдельная политика повторений.
- `api/plannerRouter.ts`: архив задачи запрещён, пока отдельно не архивированы дочерние задачи. Сброс должен атомарно обработать дерево, привязанные `scheduledBlocks` и `plannedStart/plannedEnd`, сохраняя shared workspace записи и историю завершённых блоков по явному правилу.
- `src/lib/offline.ts`: очередь содержит `planner.tasks.create/reorder/undoReorder`, но не имеет механизма tombstone/версии сброса; воспроизведение старой очереди способно вернуть задачу после архива. Нужна серверная граница операции и очистка/карантин очереди данного профиля.
- `src/pages/Today.tsx` исключает завершённые и просроченные задачи из отдельных представлений; критерий «все личные задания» должен явно охватывать завершённые/просроченные личные задачи, иначе останется неоднозначный остаток.
- На расписании видны разовые события `Только 2026-11-01`; это данные расписания, которые сброс не должен затрагивать. Общие задачи также должны быть исключены по workspace принадлежности, а не только по текущему owner.

## Не проверено

Главная, задачи (список/доска/матрица), проекты, неделя, деньги, меню и формы; размеры 360/390/768/1280/1440 px, масштаб 125/150%, клавиатурная работа dropdown/calendar/dialog, длинные русские названия и суммы. Нужен вход в production аккаунт (если текущий сеанс не авторизован) и отдельный безопасный fixture/локальная копия для заполненных экранов. Production данные не читать массово и не менять.

## Безопасная политика начала ноября

Сейчас isDeleted не является полноценным обратимым архивом: отсутствуют batchId, снимок связей и маршрут restore. exportData не содержит templates, scheduledBlocks и exceptions, поэтому JSON-экспорт не заменяет резервную копию.

Предложение: архивировать все существующие личные разовые задачи текущего профиля (включая done, просроченные, без срока, проектные и дочерние), но только `ownerId=currentUser AND workspaceId IS NULL AND isDeleted=false`. Дополнительно исключать задачи общих проектов и останавливать preview при неоднозначных owner/workspace или связях с shared-записями. `visible()` применять для сброса нельзя; `privateScope()` в одиночку тоже недостаточен, поскольку включает собственные общие задачи.

Общие задачи, включая созданные пользователем, сохранить у обоих участников. Для чистого личного представления предложен фильтр «Личные» с явным счётчиком оставшихся общих задач. Это изменение представления, не скрытое удаление работы друга.

Шаблоны повторов сохранить. Уже материализованные экземпляры с due>=2026-11-01 и их шаги сохранить; старые экземпляры архивировать. Генератор одного дня недели может уже создать 02.11 и 09.11. При архивировании этих ID createOnce не восстановит их. Регулярная ноябрьская работа — явное исключение из пустого списка; должно быть ровно одно задание Пн 09:00 с пятью шагами.

Сохранить scheduleItems/exceptions, проекты/этапы, transactions/recurringBills, timeLogs, дневник, профили/членство/приглашения, templates и dayClosures. Архивировать связанные активные блоки выбранных задач, сохраняя исторические завершённые блоки. Снимок до операции хранит дерево, зависимости, MIT, plannedStart/End и изменённые блоки. Restore проверяет версии записей и конфликты времени, не перезаписывает новые изменения молча.

Офлайн: quarantine только старых task create/reorder/undo для данного профиля; новые устройства/вкладки защищаются серверной версией taskEpoch, не только локальным удалением очереди. Денежную очередь и другие профили не очищать. Старые reorder/daily.undo/reflow не должны возвращать архив после операции.
