# Аудит интерфейса и начало нового месяца — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Завершить аудит UI «Ритма», исправить подтверждённые дефекты и предоставить обратимый архив личных задач для нового месяца.

**Architecture:** Аудит завершить отдельно от реализации; текущий частичный отчёт — `docs/superpowers/plans/2026-11-01-ui-audit-findings.md`. Сброс реализовать как идемпотентную, журналируемую транзакцию для личных задач текущего профиля, включая дерево и активные блоки планировщика. Общие workspace-задачи оставить без изменений; офлайн-очередь защитить от повторного создания архивированных задач.

**Tech Stack:** Hono, tRPC, Drizzle, MySQL, React, Railway.

**Spec:** Последний запрос пользователя: аудит в новом чате, особое внимание отступам, сброс всех заданий для начала нового месяца; сначала план, затем работа.

**Проверенное состояние:** `HEAD=314206eb6650801cc78f1d1ff0a27883709182de`; dirty только переданный план. Production UI проверен read-only на `/schedule` для 01.11.2026. Версия Railway относительно HEAD не подтверждена. Полный UI-аудит остаётся незавершённым.

## Ограничения

- Дата начала месяца: 01.11.2026, часовой пояс Asia/Dushanbe.
- На текущем этапе подготовить план и аудит; реализация следует отдельным этапом.
- Сброс касается задач пользователя. Чужие личные задачи и общие задачи нельзя массово изменять от имени другого участника.
- Предлагаемый способ сброса — архив с восстановлением, а не физическое удаление истории.
- Расписание пар, проекты, деньги, профили, платежи и шаблоны сохраняются. Удаление этих сущностей пользователь не запрашивал.
- Повторяемые задачи должны продолжать появляться по расписанию после начала месяца.
- Нельзя выполнять массовую очистку при старте контейнера, миграции или каждом открытии страницы.

## На что обратить особое внимание

- Архивированные задачи не должны возвращаться через bootstrap, офлайн-очередь или генерацию повторений.
- После очистки задача не должна оставаться в плане дня, MIT, проектном дереве и счётчиках активных задач.
- Длинные русские названия, денежные суммы и значения select должны помещаться в узких карточках.
- Dropdown, календарь и модальное окно должны оставаться в пределах экрана и работать с клавиатурой.
- Общие задачи должны одинаково отображаться у обоих участников; личные данные остаются изолированными.
