# Ожидаемая оплата проекта

Пользователь хочет записывать оплату, которую получит после сдачи проекта, отдельно от реально полученных денег. Продолжается авторизованная публикация и исправление форм; добавление друга проверяется без создания приглашений от имени пользователя.

Решение: transactions.status = posted|pending (по умолчанию posted для совместимости), expectedOn — необязательная дата ожидаемой оплаты. Pending разрешён только для дохода. Bootstrap возвращает pendingTransactions отдельно; существующие денежные расчёты получают только posted. На проекте кнопка «Ожидаемая оплата» открывает доход с выбранным проектом. В быстром добавлении дохода явно выбирается «Ожидаю оплату» / «Уже получил»; по умолчанию ожидание. На странице денег ожидаемые оплаты показаны отдельно с кнопкой «Деньги получены». Уже записанный доход можно перевести обратно в ожидание, без удаления строки и без автоматического изменения пользовательских операций при деплое.

Проверки: старые доходы/расходы остаются posted; pending не влияет на фактический доход, остаток и бюджет; повтор отметки получения идемпотентен; при получении фиксируется текущая дата; ожидание имеет собственную дату и валюту; расход не может стать pending. SQL-миграцию проверить на локальной тестовой БД, запись production-операций не выполнять. После тестов/check/build/lint опубликовать и подтвердить Railway SHA/health и формы без отправки денег.
