# Ритм: план реализации без ИИ

Исходная база — архив OKComputer, Hono + tRPC + Drizzle/MySQL + React/Vite.
Основной PDF задаёт продукт и визуальное направление; уточнённое ТЗ из сообщения
задаёт стек и приоритет дополнительных модулей. ИИ исключён пользователем.
Работа ведётся в распакованной копии; исходные PDF и ZIP сохранены.

## Решения

- Сохранять компоненты, Manrope, терракотовые токены, светлую и тёмную темы.
- Три модуля доступны из «Ещё», отключаются в настройках и на прямом маршруте.
- Денежные значения новых модулей — целые сотые, расчёты отдельно по валютам.
- Даты событий — календарные даты; моменты сделок — ISO с часовым поясом.
- Серверные записи защищены общей проверкой сессии и zod; UUID генерирует клиент.
- Повтор create не изменяет существующую запись. Платежи нельзя смешивать по валютам.
- Офлайн-очередь сохраняет порядок, останавливается на ошибке, не теряет записи;
  сервер проверяет ограничения золота повторно при синхронизации.
- Золото — журнал; риск вводится вручную, подключения к брокеру нет.
- Выполненные сделки агентства входят в прибыль месяца по дате завершения.
- Процент общего погашения при нескольких валютах показывается отдельно для
  каждой валюты: общего денежного итога без курса не существует.

## Порядок и проверки

- [ ] Агентство: контракты и тесты, таблицы и API, UI, настройки, экспорт, внимание.
  Затем `npm run check` и `npm run test`.
- [ ] Золото: контракты и тесты, журнал, баланс, правила, серверный стоп,
  подтверждение обхода, графики и экспорт. Затем check и test.
- [ ] Долги: контракты и тесты, долги, платежи, атомарный расход, графики,
  напоминания и экспорт. Затем check и test.
- [ ] Интеграция: миграции, проверка офлайн-повтора и авторизации, PWA,
  мобильный и тёмный вид, check/test/build, инструкция запуска и отчёт.

## Проверка рисков

Нулевой депозит и отсутствующий баланс дают «нет данных», а не бесконечность.
Просроченные/переплаченные долги не дают отрицательного остатка.
Удалённые родители не принимают новые платежи. Повтор UUID не создаёт расход.
Пересечение полуночи считается по timezone настройки, а не timezone сервера.
Отклонённая сервером офлайн-запись остаётся в очереди с видимой ошибкой.

## Журнал

- Базовый архив распакован без перезаписи файлов. Git-репозитория в поставке нет.
- Источники прочитаны, извлечённый текст PDF сохранён в docs/sources.
- Добавлены модули агентства, журнала золота и долгов; ежедневное планирование,
  исключения расписания, быстрый ввод, офлайн-очередь и отменяемое перетаскивание.
- Подготовлены Railway Docker deploy и повторяемые миграции MySQL; исходные суммы
  мигрируются в сотые один раз. AI-функции и интеграция с брокером отсутствуют.
- Ошибка офлайн-синхронизации теперь остаётся в постоянном индикаторе с ручным
  повтором; очередь не очищается при серверном отказе.
- Для задач доступны зависимости: сервер блокирует циклы, раннее завершение,
  возврат зависимости в работу и архивирование задачи, на которую ссылаются;
  старый снимок порядка отклоняется при изменении в другой вкладке.
- Добавлены подзадачи в редакторе задачи с прогрессом; нельзя закрыть родителя,
  пока остаются незавершённые шаги. Схема обновлена миграцией 0005.
- В агентстве добавлен график завершённой прибыли за 30 дней, без сложения валют.
- 30 октября: `npm run check`, 36 unit-тестов, production build; проверены чистая
  установка и обновление старой схемы на локальных тестовых БД. Production startup
  отдаёт health OK и SPA deep links при работающей БД.
- Осталось для полноценного выпуска: ручная приёмка на телефоне и в обеих темах,
  проверить/закрыть не реализованные пункты дней 4–12 и выполнить Railway deploy
  в аккаунте пользователя. Deployment пока не выполнялся.
